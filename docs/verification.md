# Verification record and limits

For readers assessing what was actually exercised. These are **retained historical observations**, not checks rerun by this documentation reorganization. Keep the renamed-source smoke, pre-rename deterministic full graphs, native tool adapters and actual model/provider probes separate. Passing one category does not imply another.

The shared operator stack remains intentionally **stopped**. Discovery and phone Intake are implemented but **not rolled out** to its live configuration. These observations do not authorize starting/reconfiguring it or changing authentication. No result below establishes unattended production, physical-phone/biometric behavior, private Tailscale HTTPS deployment, vendor/GPU parity, credentialed GitHub delivery or a complete real-model phone/discovery graph.

## Reading the evidence categories

| Category | Establishes | Does not establish |
| --- | --- | --- |
| Unit/race/static/build/transport tests | Tested deterministic behavior, failure transitions and compatibility | Deployed behavior, authentication or actual model reasoning |
| Renamed-source isolated smoke | Fresh namespace/CLI/UI wiring and passkey sign-in requirement | Existing-installation migration or full workflow repetition |
| Deterministic semantic full graph | Joined native UI, actual WebAuthn crypto, durable authority and real local execution/Git effects | Live semantic model decisions or physical phone |
| Pinned native runtime/tool-adapter checks | Scoped tools and byte-paged input behavior against the pinned runtime | Full model graph or production acceptance |
| Restricted actual model probe | Only the observed scoped read/research/question path | Broader execution, Astra subscription or fallback |
| Native BB provider failure | Worker/model propagation and rejection without accepted authority | Successful scoped read, draft or generation |

HTTP, raw WebSocket and SSE boundary tests are deterministic transport evidence. Native CTAP2 virtual authenticators exercise real WebAuthn cryptography but are not physical phones or biometrics. Model-shaped fixture thread IDs are not proof of native BB model success. Synthetic/provider fixtures never establish physical GPU, payment or production acceptance. Current trust and operator procedures are in [Security](security.md), [Operations](operations.md) and [Phone intake](phone-intake.md).

### Deterministic full graph with real native boundaries

The isolated installed BB browser workflow used **deterministic semantic workers**, not live model reasoning. It did use actual BB UI, controller/SQLite/CAS, WebAuthn cryptography, public HTTP/GitHub capture, Python execution/checks and private Git delivery:

- **Save and restart:** Save consumed no model reservation. Browser close/reopen and normal controller restart recovered the same durable receipt, session/auth generation and text.
- **Feature and Plan:** A Feature reached checked/reviewed Git delivery. A question-bound Plan answer made a new unapproved revision and then two unapproved children; only the explicitly approved child ran.
- **Program revision and worker recovery:** A Program answer required new revision approval. Fresh exact UP+UV recovery resumed one settled failed research worker without resetting budgets/history. Four actual public captures included commit-resolved GitHub blob identity; captured bytes were not substituted with snippets.
- **Architecture, experiment and product gates:** Architecture and each frozen experiment required separate approvals. Actual Python receipts produced **one conclusive falsification and two supported predicates**. Failed contract evaluation blocked publication until its exact settled worker was reviewed/retried. The published product initially had zero attempts and no Feature policy; implementation required separate ordinary approval.
- **Real local Git receipts:** Three products ultimately reached checked/reviewed Git delivery, ending at bare `main` **`ae0d5ec6b967d793db43786064d88fe79033ffa8`**. The main Program retained **13 logical model reservations, 14 steps and 3 experiment steps**. The complete fixture recorded **49 unique dispatch keys** under an explicit **120-call allowance**, **zero actual model calls**, and **16 verified UP+UV grants**, with **no non-UV grants**. That fixture allowance is not the live operator's thirty-call policy.
- **Concurrency and response loss:** Two independently enrolled browser contexts writing one request yielded one success and one stale-version rejection. Truncated responses, duplicate POSTs and close/reopen recovered one durable draft dispatch. Concrete capacity waits retained owned cancellation until settlement, then admitted once.
- **Limits and prerequisites:** Actual daily/lifetime waits and missing GPU/account prerequisites produced no unauthorized calls or physical executions.
- **Private disclosure:** A declared private bundle had zero model reads before exact context/bundle consent, then one complete bound read; unconsented reads stayed zero.
- **Attachment confinement:** An actual uploaded BB HTML attachment executed with `self.origin === "null"`; cookie access and credentialed privileged fetch failed.
- **Revocation and restore:** Device revocation/full auth-generation restore rejected old sessions and old passkeys. Fresh trusted-CLI-confirmed enrollment recovered access; an old-generation unsent intent stayed unresolved after reload without automatic POST replay.

The Python executable's binary identity was observed; image identity remained operator-declared, not OCI-attested. These are emulated-browser/native-fixture observations, not physical-phone, private Tailscale HTTPS, full-real-model, vendor/GPU or production qualification.

### Native BB route provider rejection

A separate production `bb.Client` → native **BB 0.47.1** → ACP probe reached a real worker and propagated the explicit Qwen model with native **medium reasoning**. OpenRouter rejected its single prompt with **HTTP 402 before any tool invocation**:

| Output-token allowance | Observed tokens |
| --- | ---: |
| Requested `max_tokens` | **131,072** |
| Provider-reported affordable maximum | **72,382** |

The actual strict intake parser rejected the provider-error text: **no draft or execution authority was accepted**. This was not a successful model response, native BB scoped nonce read or full real-model workflow. The earlier direct ACP success is separate evidence. No retry/fallback, billing/login/default-model change or token-setting change was made. The route's generation allowance or provider credits require operator review before piloting it; the failure must not be hidden or relabeled success.

## Contribution and qualification boundary

Tests must exercise behavior and failure transitions rather than copied constants or source-text wiring. Local bare Git and HTTP fixtures are valuable deterministic evidence, not a substitute for pinned BB/omp integration, actual models or independent production qualification. Record exactly which crypto/UI/native execution/model boundaries were joined in a run; never merge their separate claims into a stronger result.
